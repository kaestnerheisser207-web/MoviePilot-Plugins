# MoviePilot Plugins

面向 MoviePilot **V3.0.1 及以上版本**的插件仓库。插件使用标准 `package.v3.json` 索引、MP SDK、定时服务及插件数据目录；通过插件市场安装和更新，不需要定制 MP 镜像。

## 云端备份后清理（CloudBackupCleanup）

下载、CD2 上传和 CMS 同步照常运行。本插件独立巡检：

1. 从 MP 整理记录及实际下载器识别本地硬链接视频。
2. 同一路径被多个种子使用时，合并关联任务，检查全部任务的完成度和所需视频清单。
3. 强制刷新115目录，逐文件比对路径、文件 ID、大小和本地完整 SHA1。
4. 核对 CMS 数据库索引及实际 STRM，确认指向同一115文件。
5. 上述条件全部完成后，才读取各关联种子的站点 HR 状态。
6. 条件未满足就保留并安排下轮检查；确认满足后，在开启自动清理的情况下移除下载任务，再删除核验通过的视频硬链接。

**默认只读核查，自动清理默认关闭。** 首次使用应限定一个种子 hash，观察完整判断结果后再扩大范围。插件不执行 CD2 写入操作，不递归删除目录，不删除未经核验的附件、NFO、图片、STRM 或115文件。

### 安装

将本仓库地址加入 MP 的插件市场配置 `PLUGIN_MARKET`，保留已有仓库地址，再从插件市场安装“云端备份后清理”。源码和索引位于 `main` 分支。

插件配置、CD2 令牌、站点 Cookie、运行队列和清理记录仅保存在自己的 MP/NAS；不要提交到 GitHub。

### 接入要求

- MP 已配置并启用 qBittorrent / Transmission，沿用已有凭证和路径映射。
- MP 采用硬链接整理，下载源与媒体库文件可在 MP 容器内访问。
- CD2 使用本地目录备份到115；相关任务必须保留源文件、保留目标文件，并关闭目标同步删除。插件在清理前读取并检查这些策略。
- CD2 API 令牌只需目录读取、运行信息、传输任务读取和备份配置读取权限。无需上传、修改、删除、账户管理等权限。
- 将 CMS 的 `cms-online.db` 以只读方式提供给 MP，例如挂载到 `/cms-index/cms-online.db`。首版适配 DELETE 日志模式及 CMS `cloud_data` 索引布局；数据库不存在、结构改变、事务繁忙均会保留资源。WAL 模式暂不放行，需要单独验证包含 WAL/SHM 的一致性接入，不能只复制主数据库。
- CMS STRM 目录需在 MP 内可见，通常为 `/video/cloud-media`。配置 CMS 地址必须与 STRM 中使用的地址一致。

映射示例（仅为通用容器路径，不含实际服务器地址）：

```json
[
  {"local": "/video/movie", "cloud": "/115open/电影"},
  {"local": "/video/tv", "cloud": "/115open/电视剧"}
]
```

若 CD2 与 MP 使用不同本地路径，可为映射添加 `cd2_source`，用于匹配 CD2 备份策略。允许目录不得包含115或其他 FUSE 云盘挂载；程序会拒绝 FUSE 路径、符号链接和不在明确允许目录中的文件。

### HR 的边界

v0.3.0 复用 H&R 助手的事件、任务和状态管理设计，以及固定版本的 CHDBits H&R Monitor 表格解析器，见 [第三方声明](THIRD_PARTY_NOTICES.md)。下载事件只保存来源，不在下载路径查询个人 HR。

- 家园：读取个人 `myhr.php` 的考核中、已达标和未达标记录，完整检查筛选页和分页。仅明确的已达标记录且无冲突才能放行；未达标/逾期继续保留。
- 彩虹岛：读取个人 `hnr.php` 的 H&R 百分比、周期、站点累计做种和剩余时间。百分比为 100% 且站点累计做种达到该条记录的要求，才认定达标。H3/H5 使用记录中的要求，不统一套用站点默认值。
- `hit_and_run` 是原始种子标记，个人达标后仍可为 true；不以 MP 默认 false、标签缺失、下载器计时或考核到期代替站点确认。
- 每次 HR 核对最多访问 50 个分页/筛选视图，响应总量最多 32 MiB；超限继续保留。家园分页的 userid 必须与当前账号页面提供的值一致。
- 页面无记录、登录失效、分页不完整、结构改变和来源冲突都返回未知并保留。旧 `absence_confirmed_sites` 配置保留兼容读取，但不再用于空列表放行。现成 Nexus 个人表如有明确已免罪记录，可提供无考核证据；不会执行任何免罪/购买请求。
- 预计截止时间由站点响应时间及该记录倒计时估算，界面明确标注。旧记录重建或重新添加下载任务不会成为新的站点考核起点。
- 删除前、每次删种和每次本地文件清理前都会重新核验站点，不复用上轮或中断前的 HR 放行缓存。

### 来源记录与旧任务补录

启用插件后，`DownloadAdded` 事件会记录下载器、hash、站点、站内种子 ID、详情页和原始 HR 标记；不保存下载密钥或 Cookie 副本。下载器备注没有详情页时仍可从持久记录定位来源。

安装前的旧任务可在标准表单的 `source_mappings` 中补录已核实的来源。支持原有字符串格式，或包含来源元数据的对象；不接受手工设置个人 HR 达标状态。

```json
{
  "tr:0123456789abcdef0123456789abcdef01234567": {
    "url": "https://ptchdbits.co/details.php?id=123",
    "site_name": "彩虹岛",
    "hit_and_run": true
  }
}
```

同一任务出现不同详情页时保留并显示冲突。原始标记、个人 HR 状态及其最近核验时间分别展示。升级保留配置、哈希缓存和清理日志；旧 HR 结果移入历史记录并重新核验，来源不足的旧清理计划暂停。

### 巡检与恢复

- 默认每30分钟巡检，每轮最多2组；可限定 hash 进行小范围核查。
- 限定 hash 时仍会读取关联种子以保护共享文件，但不会清理名单外的任务；关联组超出限定范围时保留，需明确扩大范围后再清理。
- 只枚举当前下载器任务，并分批与 MP 历史关联；不会按目录名称盲扫删除旧文件。
- 初次完整哈希读取默认上限16 MiB/s；CD2 有未完成上传时推迟新的哈希计算，计算过程中也会检查新上传任务。文件身份未变化时复用已校验哈希。
- 上传完成通知不是唯一依据。记录“首次确认云端完整的时间”，不把源文件修改时间伪装成上传完成时间。
- 删除前保存清理计划和步骤；网络超时后先查询实际任务状态。删除结果不明确且任务仍存在时不自动重发，页面显示需要检查。任务已确认消失时可继续核验并完成剩余文件步骤。
- 任务被重新添加、文件选择变化、新辅种出现、文件被替换、云端状态变化或 CD2 删除策略变化时停止清理。
- 更新插件不会覆盖插件数据目录中的队列与记录。关闭自动清理后，未完成删除流程暂停；关闭插件会发出停止信号。

### 验证

```bash
python -m pip install 'beautifulsoup4>=4.12,<5'
python -m unittest discover -s tests/v3/cloudbackupcleanup -v
python -m compileall -q plugins.v3
```

测试涵盖：上传/CMS未通过时不调用 HR、HR分页/登录失败、跨站凭证保护、交叉做种分组、文件选择改变、同 hash 任务重建、文件替换/符号链接、删除结果不明确、清理中断恢复、关闭巡检及默认只读。

本仓库测试只在临时目录执行文件删除，不操作实际媒体。CI 通过、MP 插件加载、实际接口读取、真实删除验收是不同阶段，需要分别验证。

## 开发约定

插件目录、类名和索引 ID 对应；修改版本时同步 `plugin_version` 与索引版本。新代码使用 MP V3 SDK 或已公开的 Oper 接口，不直接查询 MP 内部 ORM Model。当前 CMS 适配器只读外部系统索引，单独隔离便于版本变化时替换。

### 与其他删除插件的关系

开启自动清理前必须解决“清理硬链接”插件的监控重叠。它可能在文件删除后继续删种、删历史或清理其他硬链接；本插件发现待删路径仍被它监控时会保留数据并显示原因。该插件的“不删除目录”只保护被动目标，不能关闭删除事件；明确排除关键词或停用重叠监控后才能放行。

此处的冲突检查只约束本插件发起的清理，无法拦截其他插件独立执行的删除。下载器从临时目录搬到完成目录也可能触发旧插件的源文件删除联动；部署这条 HR 保护链路时，应关闭会绕过 HR 核验的旧删种/删文件入口。
